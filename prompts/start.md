# Start Competition Research

Treat the user's competition name, URL, screenshot, document or other reference as a request to research that competition in this repository. Do the work; do not merely propose a plan or ask the user to assemble inputs or choose prompts.

1. Read root AGENTS.md, [repository-structure.md](repository-structure.md), [core.md](core.md) and the shared contract in [README.md](README.md). Resolve the reference to an official competition, year, track and evaluation version. For screenshots, inspect visible details and verify against primary sources; do not treat pictured ranks/scores as verified final results. Ask one concise clarification only if materially different identities remain plausible; continue independent work while waiting.
2. Search the existing catalog and research artifacts. Reuse the stable ID and resume from state.json when present; check source freshness. Otherwise create a schema-valid discovery record and substantive research artifacts in the prescribed locations, including the reserved latex/ directory (.gitkeep until used). Do not start a broad catalog expansion. Write the LaTeX report/figures when requested; reserving the directory does not require compiling a report.
3. Assemble stage inputs yourself from the repository and available sources, including previous state, tools and resource limits. Default to Vietnamese explanations, static public-source research, no model training or bulk dataset/weight downloads. Do not ask for a GPU budget to begin source research.
4. Apply stage prompts sequentially as needed: discovery/curation → task-and-metric/dataset → solution-forensics → reverse-engineering/experiment-design → cross-team/knowledge-extraction → evidence-audit. Continue through feasible stages without confirmation at each stage. Aim to compare the verified top three teams, subject to source availability. Follow user-specified scope if different.
5. Update canonical reports, sources, claims and resumable state. Explain the task and metric clearly, trace implementation details, separate published/measured statistics and VERIFIED/INFERRED/UNKNOWN claims. Record missing data/code precisely and continue unaffected analysis; never invent completeness or results.
6. Audit evidence and local links, run applicable existing validation/build commands, and finish with report links, key lessons, unresolved blockers and the next actionable step. Leave unfinished modules partial/blocked with reasons so the next chat can resume.
