          <h1 id="problem-description">Problem description</h1>
<p>The objective of this competition is to forecast energy consumption from varying amounts of "cold start" data, and little other building information. That means that for each building in the test set you are given a small amount of data and then asked to predict into the future. Since this format of test data is a bit unusual, we'll give an overview here, with more detail below. Here is a visual representation of the data setup for this problem:</p>
<p><img src="https://s3.amazonaws.com/drivendata-public-assets/mlscheme.png" alt="train test timing"/></p>
<p>The test data includes:</p>
<ul>
<li><code>cold_start_test.csv</code> - Cold start measurements of building consumption data (in watt-hours) and temperature. The cold start data is provided at an hourly time step over a period of anywhere from 1 day to 2 weeks. For example, if 2 days of cold start data are provided for <code>series_id</code> A, then you will have 24 * 2 = 48 consumption measurements to get your prediction started. If 2 weeks of cold start data is provided for <code>series_id</code> B, then you will have 24 * 7 * 2 = 336 consumption measurements to get your prediction started. Cold start data only comes in full days, e.g., there is no site with 2.5 days worth of cold start data, but there are sites with 1 day, 2 days, 3 days, etc., up to 14 days.</li>
<li><code>submission_format.csv</code> - This provides the structure your predictions need to satisfy to be evaluated successfully. You will have <code>series_id</code> and <code>timestamp</code> columns to help you check that your predictions take place over the correct window. Note that the <code>series_id</code> is not a unique index, but <code>series_id</code> together with <code>timestamp</code> is unique (no timestamp appears twice in the same series). Additionally, there is the <code>consumption</code> column where your hourly, daily, or weekly predictions will go. The submission format also includes measured average temperatures for each prediction in the <code>temperature</code> column. Finally, we include a <code>prediction_window</code> column to help indicate what level of temporal aggregation we want you to predict.</li>
</ul>
<p>As we'll cover below, limited additional meta data about each building in the test set is provided in <code>meta.csv</code>. Additionally, large amounts of consumption data for other sites is provided in <code>consumption_train.csv</code>.</p>

<p><a id="features_list"></a></p>
<h2 id="overview">Overview</h2>
<hr />
<p>Three time horizons for predictions are distinguished. The goal is either:</p>
<ul>
<li>To forecast the consumption for each hour for a day (24 predictions).</li>
<li>To forecast the consumption for each day for a week (7 predictions).</li>
<li>To forecast the consumption for each week for two weeks (2 predictions).</li>
</ul>
<p>In the test set, varying amounts of historical consumption and temperature data are given for each series, ranging from 1 day to 2 weeks. The temperature data contains a portion of wrong / missing values.</p>
<p>In the training set, 4 week series of hourly consumption and temperature data are provided. These series can be used to create different cold start regimes (varying amounts of provided data and prediction resolutions) for local training and testing.</p>
<p>Basic building information such as suface area, base temperature, and on/off days are given for each series in the training and test sets.</p>
<p><a id="datasets"></a></p>
<h2 id="datasets">Datasets</h2>
<h3 id="historical-consumption">Historical Consumption</h3>
<p>Time series data of consumption and temperature data identified by their <code>series_id</code>.</p>
<p><code>consumption_train.csv</code></p>
<ul>
<li><code>series_id</code> - An ID number for the time series, matches across datasets</li>
<li><code>timestamp</code> - The time of the measurement</li>
<li><code>consumption</code> - Consumption (watt-hours) since the last measurement</li>
<li><code>temperature</code> - Outdoor temperature (Celsius) during measurement from nearby weather stations, some values missing</li>
</ul>
<h3 id="building-metadata">Building Metadata</h3>
<p>Additional information about the included buildings in the train and test set.</p>
<p><code>meta.csv</code></p>
<ul>
<li><code>series_id</code> - An ID number for the time series, matches across datasets</li>
<li><code>surface</code> - The surface area of the building (ordinal)</li>
<li><code>base_temperature</code> - The base temperature that the inside of the building is set to (ordinal)</li>
<li><code>monday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>tuesday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>wednesday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>thursday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>friday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>saturday_is_day_off</code> - Whether or not the building is operational this day</li>
<li><code>sunday_is_day_off</code> - Whether or not the building is operational this day</li>
</ul>
<h3 id="cold-start-test-data">Cold Start Test Data</h3>
<p>Test data used to start a forecast. Includes metadata about prediction window as well as time series data on consumption.</p>
<p><code>cold_start_test.csv</code></p>
<ul>
<li><code>series_id</code> - An ID number for the time series, matches across datasets</li>
<li><code>timestamp</code> - The time of the measurement</li>
<li><code>consumption</code> - Consumption (watt-hours) since the last measurement</li>
<li><code>temperature</code> - Outdoor temperature (Celsius) during measurement from nearby weather stations, some values missing</li>
</ul>
<h3 id="external-data">External data</h3>
<p>In general external data is not allowed in this competition, but there are two exceptions.</p>
<ul>
<li>Holidays: competitors may use lists of holidays if desired. However, the geographic location of the data is not provided.</li>
<li>Pretrained models: competitors may use pretrained models as long as the model and the weights can be released under an <a href="https://opensource.org/licenses">open source license</a>.</li>
</ul>
<p><a id="metric"></a></p>
<h2 id="performance-metric">Performance metric</h2>
<hr />
<p>The performance metric is a normalized version of mean absolute error. The normalization coefficient |$c_{i}$| for the |$i^{\text{th}}$| prediction is composed of a ratio of two numbers,</p>
<p>$$
c_i = \frac{w_i}{m_i}
$$</p>
<p>where |$w_i$| is a weight that makes weekly (24 / 2), daily (24 / 7), and hourly (24 / 24) predictions equally important, and |$m_i$| is the true mean consumption over the prediction window under consideration (this mean is unknown to competitors). Multiplying predictions by <strong>this coefficient makes each prediction equally important</strong> and puts hourly, daily, and weekly predictions on the same scale.</p>
<p>Given the above definition, the metric |$NMAE$| is</p>
<p>$$
NMAE = \frac{1}{N} \sum_{i=1}^{N}|\hat{y_i} - y_i|c_i
$$</p>
<ul>
<li>|$N$| - The total number of consumption predictions submitted, including all hourly, daily, and weekly predictions</li>
<li>|$\hat{y}$| - The predicted consumption value</li>
<li>|$y$| - The actual consumption value</li>
<li>|$c$| - The normalization coefficient that weights and scales each prediction to have the same impact on the metric</li>
</ul>
<p><a id="format"></a></p>
<h2 id="submission-format">Submission format</h2>
<hr />
<p>The submission format is such that <code>series_id</code> together with <code>timestamp</code> is unique (no timestamp appears twice in the same series). We have provided the index <code>pred_id</code> for simplicity. Additionally, there is the <code>consumption</code> column where your hourly, daily, or weekly predictions will go. The <code>temperature</code> column reports the average temperature for that time period. The <code>prediction_window</code> column includes how often predictions need to be made (can be inferred from the timestamps).</p>
