          <h1 id="problem-description">Problem description</h1>
<p><strong>Your goal in this challenge is to use satellite imagery to detect and classify the severity of cyanobacteria blooms in small, inland water bodies.</strong> This will help water quality managers better allocate resources for in situ sampling and make more informed decisions around public health warnings for drinking water and recreation. </p>
<p>Overview of the data provided for this competition:</p>
<pre><code>.
├── metadata.csv
├── submission_format.csv
└── train_labels.csv
</code></pre>
<p><a id="metadata"></a></p>
<h2 id="metadata">Metadata</h2>
<hr />
<p>Labels in this competition are based on “in situ” samples that were collected manually and then analyzed for cyanobacteria density. Each measurement is a unique combination of date and location (latitude and longitude). Samples come from water bodies throughout the continental U.S., and date back to 2013.</p>
<p><code>metadata.csv</code> includes attributes for all of the sample measurements in the data. It has the following columns:</p>
<ul>
<li><strong><code>uid</code> (str):</strong> unique ID for each row</li>
<li><strong><code>latitude</code> (float):</strong> latitude of the location where the sample was collected</li>
<li><strong><code>longitude</code> (float):</strong> longitude of the location where the sample was collected</li>
<li><strong><code>date</code> (pd.datetime):</strong> date when the sample was collected, in the format YYYY-MM-DD</li>
<li><strong><code>split</code> (str):</strong> indicates whether the row is part of the train set or the test set</li>
</ul>
<p>Metadata is provided for all points in both the train and test sets. Labels are only provided for rows in the train set.</p>
<p>The basic steps for completing a submission are to:</p>
<ol>
<li>Train your model on the train dataset</li>
<li>Generate predictions for the test dataset</li>
<li>Submit those predictions for scoring</li>
</ol>
<p>Each geographic area is either entirely in the train set or entirely in the test set. This means that none of the test set locations are in the training data, so your model's performance will be measured on unseen locations.</p>
<p><a id="feature-data"></a></p>
<h2 id="feature-data">Feature data</h2>
<hr />
<p>The feature data for this challenge is a combination of satellite imagery, climate data, and elevation data. <strong>Sentinel-2 is the only required data source — using any of the additional sources below is up to you!</strong> The four approved data sources are:</p>
<ul>
<li><a href="https://www.drivendata.org/competitions/143/tick-tick-bloom/page/650/#sentinel-2-1">Sentinel-2</a> satellite imagery</li>
<li><a href="https://www.drivendata.org/competitions/143/tick-tick-bloom/page/650/#landsat-1">Landsat</a> satellite imagery</li>
<li><a href="https://www.drivendata.org/competitions/143/tick-tick-bloom/page/650/#climate-data-1">NOAA's High-Resolution Rapid Refresh (HRRR)</a> climate data</li>
<li><a href="https://www.drivendata.org/competitions/143/tick-tick-bloom/page/650/#elevation-data-1">Copernicus DEM</a> elevation data</li>
</ul>
<p><strong>Participants will access all feature data through external, publicly available APIs. You may only use the approved access points specified.</strong> The section on each data source lists which external APIs it is available through. To pull data about each of the sample points, search an API using the sample's location and date from <code>metadata.csv</code>.</p>
<p><strong>To predict the density of a given sample, you may only use data that was available at the time the sample was collected.</strong> For example, if a given sample was collected on October 18, 2022, you may only use data that was collected on or before October 18, 2022. Date range can be included in your queries to external APIs.</p>
<blockquote>
<p><em>Tip:</em> When there are multiple access point locations for a data source, download from the one that is geographically closest to you to reduce download times.</p>
</blockquote>
<div class="alert alert-info">
<strong>Note on external data:</strong> External data that is not one of the four sources listed below is not allowed in this competition. Participants can use pre-trained computer vision models as long as they were available freely and openly in that form at the start of the competition.
</div>

<p><a id="satellite-imagery"></a></p>
<h3 id="satellite-imagery">Satellite imagery</h3>
<p>The satellite data for this competition includes Sentinel-2 and Landsat. Visible spectrum imagery in Sentinel-2 has a higher resolution than Landsat (10 meters compared to 30 meters). However, for data points prior to mid-2016, only Landsat imagery is available.</p>
<p>Sentinel-2 and Landsat satellites revisit the same location roughly every five and eight days respectively, so in most cases imagery is available within a few days of the in situ sampling label. Imagery captured within a ten-day range is still generally an accurate representation of the sampling conditions.</p>
<p>For each satellite source, participants can use either level-1 or level-2 data. </p>
<ul>
<li>
<p>Level-1 describes <strong>top of atmosphere reflectance</strong>, which can be thought of as the “raw” reflectance. It is a mix of light reflected off of the Earth’s surface and off of the atmosphere.</p>
</li>
<li>
<p>Level-2 describes <strong>bottom of atmosphere reflectance</strong>. To generate level-2 data, an atmospheric correction model is applied to level-1 that eliminates some of the effects of the atmosphere on reflectance values.</p>
</li>
</ul>
<p>Level-2 data generally captures conditions on the Earth’s surface more accurately. However, the atmospheric correction algorithms applied to level-2 can also sometimes reduce the visibility of bright algal blooms.</p>
<p><a id="sentinel-2"></a></p>
<h4 id="sentinel-2">Sentinel-2</h4>
<p><a href="https://docs.sentinel-hub.com/api/latest/data/sentinel-2-l2a/">Sentinel-2</a> is a wide-swath, high-resolution, multi-spectral imaging mission. Sentinel-2’s publicly available level-1 data is called <a href="https://docs.sentinel-hub.com/api/latest/data/sentinel-2-l1c/">Level-1C (L1C)</a>, and the publicly available level-2 data is called <a href="https://docs.sentinel-hub.com/api/latest/data/sentinel-2-l2a/">Level-2A (L2A)</a>.</p>
<p>In addition to bottom-of-atmosphere reflectance, Sentinel-2 L2A also includes algorithmic bands that describe environmental features relevant to the behavior of algal blooms.</p>
<ul>
<li>
<p><strong>Scene classification (SCL)</strong>: The scene classification band sorts pixels into categories including water, high cloud probability, medium cloud probability, and vegetation. Water pixels could be used to calculate the size of a given water body, which impacts the behavior of blooms. Vegetation can indicate non-toxic marine life like sea grass that sometimes resembles cyanobacteria.</p>
</li>
<li>
<p><strong><a href="https://docs.sentinel-hub.com/api/latest/user-guides/cloud-masks/">Cloud masks (CLM)</a></strong>: Sentinel-2’s cloud bands can be used to filter out cloudy pixels. Pixels that are obscured by clouds are likely not helpful for algal bloom detection because the actual water surface is not captured.</p>
</li>
</ul>
<p><strong>Data access details</strong></p>
<ul>
<li>Microsoft’s <a href="https://planetarycomputer.microsoft.com/docs/overview/about">Planetary Computer</a> provides access to Sentinel-2 L2A, but not Sentinel-2 L1C.<ul>
<li>Approved data access location: <code>https://planetarycomputer.microsoft.com/api/stac/v1/collections/sentinel-2-l2a</code></li>

</ul>
</li>

</ul>
</li>
</ul>
<p><a id="landsat"></a></p>
<h4 id="landsat">Landsat</h4>
<p><a href="https://www.usgs.gov/landsat-missions">Landsat</a>, a joint NASA/USGS program, provides the longest continuous space-based record of Earth’s land in existence.</p>
<p>There have been many Landsat missions since the original launch in 1972. The competition data goes back to 2013.</p>
<ul>
<li>
<p><strong>For data from March 2013 or later, participants may only use <a href="https://www.usgs.gov/landsat-missions/landsat-8">Landsat 8</a> and <a href="https://www.usgs.gov/landsat-missions/landsat-9">Landsat 9</a></strong>. Landsat 8 and Landsat 9 satellites are out of phase with one another, so that between the two each point on the Earth is revisited every 8 days. The data collected by Landsat 9 is very similar to Landsat 8.</p>
</li>
<li>
<p>For data from January and February of 2013, participants may also use <a href="https://www.usgs.gov/landsat-missions/landsat-7">Landsat 7</a> in addition to Landsat 8 and Landsat 9. These early samples may predate the launch of Landsat 8. Landsat 7 may not be used for any later data.</p>
</li>
</ul>
<p>Participants may not use any Landsat missions besides those listed above. <strong>Participants may use either level-1 or level-2 data, but may not use level-3.</strong> In addition to bottom-of-atmosphere reflectance, Landsat level-2 also includes a measurement of surface temperature, which is relevant to the behavior of algal blooms.</p>
<p><strong>Data access details</strong></p>
<ul>
<li>Microsoft’s <a href="https://planetarycomputer.microsoft.com/docs/overview/about">Planetary Computer</a> provides access to Landsat level-1 and level-2 data.<ul>

<p><a id="performance-metric"></a></p>
<h2 id="performance-metric">Performance metric</h2>
<hr />
<p>To measure your model’s performance, we’ll use <strong>Region-Averaged Root Mean Squared Error (RMSE)</strong>. RMSE is the square root of the mean of squared differences between estimated and observed values. This is an error metric, so a lower value is better. RMSE is implemented in <a href="https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_squared_error.html">scikit-learn</a>, with the squared parameter set to <code>False</code>.</p>
<p>RMSE will be calculated separately for each of the four regions of the U.S. shown below and then averaged.</p>
<p>$$
\text{Region-Averaged RMSE} = \frac{1}{M} \sum_{m=0}^M \sqrt{\frac{1}{N} \sum_{n=0}^N (y_{nm} - \hat{y}_{nm})^2 }
$$</p>
<p>where:</p>
<ul>
<li>|$\hat{y}_{nm}$| is the predicted severity level for the |$n$|th sample in the |$m$|th region</li>
<li>|$y_{nm}$| is the actual severity level for the |$n$|th sample in the |$m$|th region</li>
<li>|$N$| is the number of samples</li>
<li>|$M$| is the number of regions</li>
</ul>
<p>This amounts to:</p>
<p>$$
\text{Region-Averaged RMSE} = \frac{\text{West RMSE} + \text{Midwest RMSE} + \text{South RMSE} + \text{Northeast RMSE}}{4}
$$</p>
<p>Region information is provided in <code>train_labels.csv</code> for the train set and in <code>submission_format.csv</code> for the test set.</p>
